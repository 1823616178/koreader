# Kindle 客户端优化与后续功能任务清单

更新日期：2026-09-06  
范围：`kindle/` 原生客户端及其设计、测试、构建与部署流程。涉及服务端的功能在对应任务中单独注明。  
状态：规划待实施；本文的建立不代表代码已修复。

## 1. 检查结论与实施原则

继续沿用 C + FBInk + KUAL / Scriptlet 架构，先修复触摸、会话恢复和配置保存，再完善刷新与异常交互，最后扩展功能。

本次检查依据：

- `kindle/src/`、`kindle/extension/bin/`、`kindle/tests/` 和 `tools/build.sh`。
- [原生客户端说明](../kindle/README.md)、[安装说明](../kindle/install.md)、[移植设计](../kindle-port.zh-CN.md)。
- [UI 与省电规划](../docs/kindle-ui-and-power.md)、[前光与电量设计](../docs/kindle-light-and-battery.md)、[卡片弹窗设计](../docs/kindle-card-popup.md)、[Usage API 契约](../docs/superpowers/plans/usage-api.md)。

已完成的检查：

- 现有 25 组主机测试全部通过，HTTP 用例使用本机临时服务。
- 使用实际 `input.c` 编译的临时库复现了交换坐标轴后的缩放错误。
- 其余问题来自代码与设计对照；会话竞争、屏幕残影、实际功耗和设备恢复尚未进行真机验证。
- 此前检查未修改项目代码。本轮仅新增本文档。

优先级定义：P0 为首先处理的操作与恢复问题；P1 为可靠性、显示正确性和交互优化；P2 为功能扩展；探索项需先完成设备或服务端验证。

以下能力已经实现，不作为新功能重复开发：自动刷新、WiFi 按需开关、闲置熄灯、前光开关与亮度步进、五格电池及充电显示、卡片放大。相关任务是修复边界或补齐验收。

## 3. 修复与优化任务

### R01：修正触摸坐标交换与缩放顺序

- [ ] **P0 · 待实施**
- 位置：`kindle/src/input.c` 的 `input_transform()`；`kindle/tests/test_main.c` 的 `test_input_transform()`。
- 问题：先按原屏幕宽高缩放，再交换坐标轴，会在非正方形屏幕上使用错误的目标尺寸。
- 已复现：600×800 屏幕、原始范围均为 0–4095、`touch_swap_xy=1` 时，原始 `(4095,0)` 实际得到 `(0,599)`，正确值应为 `(0,799)`；原始 `(2048,2048)` 实际为 `(399,299)`，正确值应为 `(299,399)`。
- 实施：先交换原始轴及其最小/最大范围，再按目标宽高缩放，最后应用镜像和边界限制。纠正现有测试中把错误结果作为预期的用例。
- 验收：覆盖非正方形屏幕、全部交换/镜像组合、四角、中心、越界和零宽范围；真机底部“刷新／设置／关闭”均可点击。
- 依赖：无。

### R02：启动器与看门狗按会话隔离

- [ ] **P0 · 待实施，竞争场景需验证**
- 位置：`kindle/extension/bin/aiquota.sh`、`watchdog.sh`、`restore.sh`；`kindle/src/watchdog.c`、`main.c`。
- 风险：旧看门狗在退出后的延迟检查中，可能恢复新会话冻结的 framework，或删除新会话共用的 `/var/tmp/aiquota.ping`。当前也缺少启动成功握手和完整的会话归属检查。
- 实施：增加单实例锁和会话标识；心跳、屏幕备份和恢复状态绑定会话；记录并核对包装脚本与应用进程身份；旧看门狗只清理本会话资源。冻结前确认看门狗就绪，并建立可监控的启动期限。手动恢复同步结束对应会话，避免残留应用继续写屏或重新保持唤醒。
- 验收：模拟正常退出后立即重开、重复启动、旧看门狗延迟退出、包装脚本被强杀、应用假死和看门狗启动失败；新会话不被旧会话恢复或清理。真机验证退出后可翻书、进入设置和息屏唤醒。
- 依赖：无；与 R11 的脚本模拟配套。

### R03：按实际显示内容判断刷新范围

- [ ] **P1 · 待实施**
- 位置：`kindle/src/main.c` 的 `frame_sig_of()`、`do_fetch()`；`kindle/src/ui.c`。
- 问题：成功响应对完整 JSON 计算签名。接口的 `generatedAt` 每次变化，即使额度相同，也会触发整屏更新。
- 实施：引入按卡片组织的显示模型，比较实际显示的额度、告警、状态和格式化文本；额度卡、时间信息与标题角标分别判断变化。时间戳和重置倒计时需有明确的显示粒度，不能直接忽略时间字段而留下错误文本。
- 验收：只改变 JSON 字段顺序或空白时不重绘；仅响应时间变化时只更新必要区域；单个提供商变化时仅更新对应卡片；提供商增减或布局变化时完整重排；电量格数与充电状态正确参与局刷。
- 真机项：根据连续轻刷的残影，确定定期清屏或手动清屏策略，并记录触发条件。
- 依赖：R11；F04 的显示偏好后续应复用此模型。

### R04：修复 WiFi 所有权与关闭失败处理

- [ ] **P1 · 待实施**
- 位置：`kindle/src/net.c` 的 `net_ensure_wifi()`、`net_release_wifi()`。
- 问题：检测到已连接就清除 `g_wifi_we_enabled`。应用自己开网并保持连接后，下一次请求会丢失所有权，随后开启“刷新后关 WiFi”可能不生效。关闭命令失败时也已经清除所有权并把显示状态置为断开。
- 实施：区分进入会话前已有连接与本会话开启的连接；成功释放之前保留所有权。根据命令结果和必要的状态确认更新显示，失败时保留后续重试能力。明确设置切换和退出时的释放策略。
- 验收：系统原本已连接时不误关；应用开网后可正常关闭；先保持连接再开启自动关闭能够生效；关闭失败时不虚报断开且后续可重试。
- 依赖：无；R02、R06 改动时需保持一致的资源清理规则。

### R05：可靠保存配置并反馈失败

- [ ] **P1，安排第一批 · 待实施**
- 位置：`kindle/src/config.c` 的 `config_save()`；`main.c` 的设置提交路径。
- 问题：直接 `fopen(path, "w")` 会先截断旧配置；写入中断可能丢失接口和触摸标定。失败目前仅输出日志，界面看不到。
- 实施：在同目录写临时文件，检查写入、刷新、关闭和替换结果，再替换正式配置；根据目标 FAT 文件系统验证持久化行为，必要时保留最近有效备份。明确保存失败时内存配置是否生效，界面提示并允许重试。
- 验收：正常保存与重新启动一致；模拟写入失败、空间不足、只读目录和中途退出时，旧配置仍可读取或恢复，界面不显示保存成功；保留所有已知配置项和触摸参数。
- 依赖：无；F01、F07 可复用可靠写入机制。

### R06：网络请求可取消，主界面保持响应

- [ ] **P1 · 待实施**
- 位置：`kindle/src/main.c`、`http.c`、`net.c`、`watchdog.c`。
- 问题：WiFi、DNS、连接和收包都同步执行；慢请求期间主线程不读触摸，关闭操作延迟。
- 实施：抽出请求管理，使用工作线程或可轮询的请求状态机；绘制仍由 UI 主线程负责。定义取消、超时、重复刷新合并、过期结果丢弃和 WiFi 清理行为。整次请求采用总期限，单次命令和网络阶段也有独立期限，避免仅依靠看门狗强杀处理正常超时。保留 API 冷启动所需的响应等待预算。
- 验收：慢响应、DNS 失败、无法连接和持续少量回包时，界面仍能响应关闭；取消后的结果不覆盖新状态；连续点击刷新不堆积请求；退出后无遗留请求和由本次请求占用的资源。
- 依赖：R02、R04、R09、R10 的生命周期规则。

### R07：信息卡弹窗完整展示长文本

- [ ] **P1 · 待实施**
- 位置：`kindle/src/ui.c` 的 `draw_info_block()`、`scale_popup_ui()`、`ui_popup_draw()`；`main.c` 的弹窗交互。
- 问题：卡片与字体一起放大，仍使用单行省略，不能满足设计中的长地址、错误文本完整可读要求。
- 实施：提供商卡片保留现有放大方式；信息卡使用独立的多行详情布局，长内容分页。若加入翻页控件，调整“点任意位置关闭”的命中规则并更新设计，避免翻页触发关闭。
- 验收：最长配置地址、长错误文本、中文和混合文本可完整读取；内容不溢出；关闭后背景正确还原；弹窗期间自动刷新和闲置熄灯仍符合约定；屏幕保存失败时可降级重绘。
- 依赖：无；F03 复用详情展示能力。

### R08：常驻期间低频更新电量与充电状态

- [ ] **P1 · 待实施**
- 位置：`kindle/src/main.c` 的 `wait_tap_until()`、`maybe_refresh_badges()` 和闲置 deadline 分支。
- 问题：首次闲置熄灯采样后，deadline 被清零；关闭自动刷新并长期无人操作时，电量仍可能一直显示旧值。
- 实施：利用已有分段等待的唤醒点，按低频采样间隔检查电量和充电状态；仅在格数或充电态变化时局部刷新。不为电量单独新增后台线程或频繁定时器。
- 验收：自动刷新关闭、无人触摸期间，插拔充电或跨电池格数变化后，在约定采样间隔内更新；同一格内百分比变化不刷新；不重新开启 WiFi；弹窗区域不被角标更新破坏。
- 依赖：R03、R09。

### R09：统一计时与页面状态管理

- [ ] **P1 · 待实施**
- 位置：`kindle/src/main.c`、`input.c`、`http.c`、`net.c`、`watchdog.c` 及 shell 看门狗。
- 问题：多处期限使用 `time(NULL)`，系统校时可能改变等待行为；主流程同时承载页面、请求、前光和刷新调度，新增功能容易产生交叉影响。
- 实施：逐步抽出调度器和页面状态，统一管理仪表盘、设置、键盘、弹窗和请求状态。持续时间使用单调时钟，接口时间和日期显示保留实时时钟；核对旧工具链的链接要求。C 与 shell 看门狗应统一时间基准，避免仅修改一侧。
- 验收：模拟系统时间前跳和后跳，自动刷新、闲置熄灯、请求超时及假死检测不被异常延长或提前；设置与弹窗期间延后的刷新返回后只补一次；跨等待分段的触摸状态有明确处理。
- 依赖：与 R06 协同设计，采用渐进改造。

### R10：按接口隔离快照与请求结果

- [ ] **P1 · 待实施**
- 位置：`kindle/src/main.c` 的 `snap`、`have_good`、设置返回与请求完成路径。
- 问题：更换接口后旧快照仍可能保留，新接口拉取失败时容易让用户误认为旧额度来自新接口；异步化后还需防止旧请求晚到覆盖新状态。
- 实施：快照和请求绑定归一化接口地址及请求代次；切换接口时清空当前快照或明确显示其来源，旧请求结果直接丢弃。缓存键保留有业务意义的 query 参数。
- 验收：从接口 A 切换到不可用的 B，不能把 A 的额度标成 B；A 的延迟响应不能覆盖 B；相同接口短暂失败时可保留最后成功数据并明确显示失败或过期状态。
- 依赖：R06；F01 在此基础上增加磁盘缓存。

### R11：补齐状态、脚本和真机验收

- [ ] **P1 · 随各批次实施**
- 位置：`kindle/tests/`、`kindle/Makefile`、`tools/build.sh`。
- 实施：保留现有单测，补充上述真实行为的回归测试；通过渲染替身或显示模型测试覆盖 `main/ui/settings` 之间的状态切换和刷新范围。脚本模拟的 framebuffer、心跳、wake lock、进程控制及设备命令必须完整替换到独立临时环境后再接入自动检查。
- 自动验收：R01 坐标、R02 会话竞争、R03 变化判定、R04 网络所有权、R05 保存失败、R06 取消请求、R08 采样、R09 时间跳变、R10 旧结果隔离均有回归覆盖。
- 真机验收：KUAL / Scriptlet 双入口，触摸四角与底部按钮，慢网关闭，WiFi 状态切换，设置与弹窗跨刷新期限，前光恢复，充电角标，连续轻刷残影，快速重启和故障恢复。
- 功耗验收：记录设备型号、固件、前光档位、WiFi 策略、刷新周期和测试时长，比较相同条件下的耗电；没有测量数据前不承诺续航增幅。
- 依赖：贯穿全部修复；现有单测通过不等于新增任务已完成。

### R12：同步设计状态、接口约定与操作说明

- [ ] **P1 · 随实现更新**
- 位置：`docs/` 下三个 Kindle 设计文档、`kindle/README.md`、`kindle/install.md` 和本文。
- 实施：统一标记“已实现／待修复／待真机验证／后续探索”；历史方案保留但明确标记。更新弹窗完整文本、电量刷新、跳帧策略、恢复流程和看门狗延迟说明，避免使用无条件的自愈或省电承诺。
- 验收：文档所述默认值、交互、超时与代码一致；每项完成状态能对应实现和验证记录；已实现功能不再混入新增功能清单。
- 依赖：各任务实施结果。

## 4. 后续功能任务

### F01：离线快照与过期标识

- [ ] **P2 · 功能第一轮**
- 价值：重启后断网仍可查看上次成功额度，并知道数据是否过期。
- 实施：按接口地址保存最后成功快照、成功时间和缓存格式版本；启动先显示缓存，再按配置拉取；无变化时减少写盘。界面区分“本次连接失败”和“缓存仍可参考”。
- 验收：断网重启能恢复正确接口的快照；过期状态清晰；缓存损坏可安全忽略；新数据成功后替换缓存；跨接口不串数据。
- 依赖：R05、R10。

### F02：机内提供商筛选与排序

- [ ] **P2 · 功能第一轮**
- 价值：直接选择关注的工具并调整卡片顺序。
- 实施：保存本机显示偏好，或构造 `/api/usage?providers=...` 请求筛选。区分“隐藏卡片”和“本次不采集”的语义；默认不修改服务端全局采集名单。AGY 两个额度组的顺序规则需明确。
- 验收：筛选和排序重启后保留；卡片命中仍对应正确提供商；全不选有明确处理；设置不改变其他客户端的全局采集配置。
- 依赖：R03、R05；检查 API 现有筛选约定。

### F03：连接诊断页

- [ ] **P2 · 功能第一轮**
- 价值：用户无需 SSH 即可区分 WiFi、DNS、连接、HTTP 和 JSON 解析问题。
- 实施：保存本次请求各阶段耗时、HTTP 状态和完整错误文本，增加手动重新检测入口。使用结构化错误，避免依靠字符串猜测失败阶段；未来加入认证时不显示凭据。
- 验收：各类失败能定位到正确阶段；长文本完整可读；诊断失败不覆盖最后成功额度；测试请求可取消。
- 依赖：R06、R07。

### F04：本机显示偏好

- [ ] **P2 · 功能第一轮**
- 价值：提供已用／剩余切换、大字模式和精简卡片模式，少量提供商时可获得更大显示空间。
- 实施：本机设置覆盖显示模式但不改变 `used` 字段语义；根据可见卡片数调整布局和字号；保持告警阈值基于已用百分比。
- 验收：0%、100%、无数据和限流状态都显示正确；模式切换不重新解释 API 数值；不同卡片数量和屏幕尺寸下内容与按钮不溢出。
- 依赖：R03、R05、F02。

### F05：刷新策略预设与失败退避

- [ ] **P2 · 功能第二轮**
- 价值：适应手动查看、常驻和夜间使用，连续失败时减少无效网络唤醒。
- 实施：提供手动、常规、夜间等预设，并保留明确的实际刷新间隔；连续失败逐步延长重试间隔，设定上限，成功后恢复；手动刷新立即执行。保持静态文字说明，不引入秒级倒计时。
- 验收：预设行为与显示一致；失败退避有上限；手动请求可绕过等待；设置或弹窗返回后不会补发多次请求。
- 依赖：R06、R09。

### F06：闲置熄灯时间可配置

- [ ] **P2 · 功能第二轮**
- 价值：允许按使用习惯调整当前固定 3 分钟的熄灯时间。
- 实施：新增 `light_idle_off_min`，建议 0 表示关闭、1–60 表示分钟数，旧配置保持 3 分钟默认值；复用设置页输入和现有前光恢复逻辑。调整设置布局以容纳新项。
- 验收：0 和边界值正确；重启后保留；设置／键盘期间仍暂停闲置计时；用户手动关灯不会被自动恢复；退出时只恢复由闲置逻辑关闭的灯。
- 依赖：R05、R09。

### F07：首次配置引导与安全升级

- [ ] **P2 · 功能第二轮，可拆为两个交付项**
- 价值：减少首次配置错误，避免升级覆盖接口地址和触摸标定。
- 实施：首次运行引导填写接口、验证连接和校准触摸；校准失败保留恢复方式。升级将默认配置与用户配置分离，增加版本信息、配置迁移和上一版本恢复能力。
- 验收：全新安装可完成连接与校准；升级保留用户配置；异常升级可恢复上一有效版本；用户配置损坏时能恢复或重新引导；升级期间不允许并发运行旧会话。
- 依赖：R01、R02、R05；涉及 `tools/build.sh` 和安装文档。

### F08：额度趋势与消耗速度

- [ ] **P2 · 功能第二轮，需服务端配合**
- 价值：展示最近一天或一周变化，帮助判断使用速度。
- 实施：历史采样、存储和计算优先放服务端；Kindle 展示简图与摘要，不承担持续历史采集。区分窗口重置造成的变化与实际消耗，接口明确时间粒度和缺失数据语义。
- 验收：时间范围和采样间隔明确；缺失数据不画成零消耗；重置点有正确处理；数据量有上限；图表在灰阶屏可读且不增加高频刷新。
- 依赖：服务端历史接口设计、R03、R06。

### F09：允许真正休眠的桌面仪表盘模式

- [ ] **探索 · 先验证后实施**
- 价值：通过定时唤醒刷新、随后继续休眠降低常驻功耗。
- 前置验证：目标机型 RTC 唤醒能力、唤醒后的 framebuffer 与触摸状态、powerd 行为、framework 冻结／恢复顺序、唤醒失败后的人工恢复方式。
- 实施方向：独立模式且默认关闭；休眠前释放适当的唤醒保持，保存下一次任务，唤醒后恢复请求与绘制。与看门狗协调，正常休眠不能被当作假死。
- 验收：跨多个休眠周期可靠唤醒并刷新；用户能恢复操作；网络失败不会持续保持唤醒；退出后系统正常休眠；相同条件下记录实际耗电差异。
- 依赖：R02、R06、R09、R11 的真机基线；未完成前置验证不承诺续航或适配范围。

### F10：HTTPS 与认证

- [ ] **按需探索 · 需服务端配合**
- 价值：满足跨网络访问时的传输保护和访问控制需求。当前客户端仅支持 HTTP，接口文档约定当前无认证。
- 前置工作：确定服务端或反向代理的认证方案、目标设备 TLS 库与证书存储条件，以及凭据的配置和更新方式。
- 实施：增加 HTTPS、证书和主机名校验、认证头、认证失败提示；明确配置存储与日志脱敏规则。不以关闭证书校验作为正式方案。
- 验收：有效证书连接成功；错误主机名、过期证书和无效凭据得到明确失败；诊断及日志不泄露凭据；目标 ARM 构建和部署依赖可重复生成。
- 依赖：R05、R06、F03，以及服务端认证方案。
