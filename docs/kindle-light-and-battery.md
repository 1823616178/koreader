## 0. 结论

**三项需求都不是「能否添加」，而是「已经在跑」。** 逐条核对见 §1：

| 需求 | 状态 | 入口 |
| --- | --- | --- |
| 屏幕背光开关 | 已实现 | 设置页「前光」行左半边 |
| 亮度控制 | 已实现 | 同一行右侧 `−` / `+` 行内步进，每点一档立刻生效 |
| 电量右上角显示 | 已实现 | 标题栏右上角百分比（**待改为五格电池条**，见 §3 G2） |
| 充电状态显示 | 已实现 | 充电时前缀「充电 N%」 |

额外已落地、需求里没提的：**闲置 3 分钟自动熄灯 + 触摸即恢复 + 退出还原**（`main.c:157`, `light.c:125-148`）。

所以本文的实际价值在 §3：这四件事**还剩哪些洞**，以及补洞的可行性。结论是有 3 项值得做（G1/G3/G4）、2 项可做可不做（G5/G8）、3 项建议不做（G2/G6/G7）。

## 1. 现状核对

### 1.1 背光与亮度

**机制**：Amazon `powerd` 的 lipc 属性，不碰 sysfs。

| 环节 | 位置 | 说明 |
| --- | --- | --- |
| 读档位 | `kindle/src/light.c:73` | `lipc-get-prop com.lab126.powerd flIntensity` |
| 读上限 | `kindle/src/light.c:88` | `flMaxIntensity`；首次成功后进程内缓存（`cached_max`），失败不缓存 |
| 写档位 | `kindle/src/light.c:100` | `lipc-set-prop -i`，写前 `light_clamp` |
| 夹取 | `kindle/src/light.c:62` | `[0, max]`；`max < 1` 用 `LIGHT_MAX_FALLBACK`(24) |
| 设置页 UI | `kindle/src/settings.c:21` `ROW_LIGHT` | 合并行：左半切换开/关，右侧 `−` 档位 `+` |
| 步进 | `kindle/src/settings.c` `step_light()` | 每次点击直发 powerd，行内 DU 局部刷新，不整页 GC16 |
| 闲置熄灯 | `kindle/src/main.c:157,788` | `LIGHT_IDLE_OFF_S = 3*60`，与自动刷新 deadline 取较早者 |
| 触摸恢复 | `kindle/src/main.c:805` | 恢复**在 hit-test 之前**，唤醒那一次点击照常命中按钮 |
| 退出还原 | `kindle/src/main.c:947` | 闲置熄的灯退出前还原；手动关的保持关 |
| 诊断 | `--dump-state` (`main.c:464`) | 打印 `frontlight_intensity=` / `frontlight_max=` |
| 测试 | `tests/test_main.c:640` | clamp 边界 + 无 lipc 环境全部返回 -1 不崩 |

两条关键设计已经做对，不要在后续改动里破坏：

1. **前光不是配置键。** powerd 自己持久化，退出应用后系统前光就是这个值。`extensions/aiquota/config` 里没有亮度行，也不该有。
2. **「用户关的」和「闲置关的」用同一个槽位区分**（`light.c:113` `idle_saved`）。非零即代表「是我们熄的」，所以恢复逻辑不可能把用户手动关掉的灯打开。

### 1.2 电量右上角

**机制**：sysfs 文件直读，不起子进程、不走 lipc。

- 路径：`/sys/devices/system/yoshi_battery/yoshi_battery0/battery_level`（`net.c:31`）
- 读取：`net_battery()` (`net.c:176`)，范围外或读不到给 -1
- 绘制：`draw_status_badges()` (`ui.c:390`)，从 `ui->w - ui->h_padding` **从右往左**排：电量 → 间隙 → SSID/WiFi 标签 → WiFi 圆点
- `batt_pct` 越界（含 -1）**什么都不画**：首次探测前和非 Kindle 环境都不留占位

**采样时机只有三处重绘点**——启动骨架 (`main.c:286`)、拉取完成 (`main.c:380`)、设置页返回 (`main.c:919`)。没有定时器、没有轮询、不制造唤醒。这是 e-ink + wake lock 形态下的正确取舍，代价见 §3 G1。

### 1.3 充电状态

- `sysfs_charging()` (`net.c:156`) 读 `battery_status`，接受三种写法：`1` / `charg*` / `full*`
- 显示：`batt_charging == 1` 时 `"充电 %d%%"`，否则 `"%d%%"` (`ui.c:401`)
- **满电算充电**：角标语义是「接在电源上」，不是「正在充进电」
- 参与跳帧判定：`frame_batt` / `frame_chg` 进签名 (`main.c:259`)，自动刷新拿回相同数据且角标没变则整帧跳过重绘。**注意**：比的是原始百分比，87→86 也算「变了」，会逼出一次本可省掉的重绘——G2 的电池条把这条改成比格数后就不再有这个问题

## 2. 为什么是这个形状（改动前先读）

| 决定 | 理由 |
| --- | --- |
| 电量走 sysfs、前光走 lipc | 电量要频繁读且只需数字，sysfs 是三次 open/read/close；前光要**改系统状态并持久化**，只有 powerd 能做 |
| 角标只在既有重绘点采样 | 常驻仪表盘的功耗形态里，任何新增周期性动作都是净损失（见 `kindle-ui-and-power.md` §1） |
| 文字而非电池图标（当前） | 字体是 `fonts/glyphs.txt` 裁出来的子集，新汉字要改子集并重裁；「充电」二字已在表内。**电池条不需要字体**（纯 `ui_fill` 矩形），所以 G2 推翻了这一条的后半段 |
| 闲置熄灯复用 `wait_tap_until` 的 deadline | 不新开线程、不新开定时器，`poll` 超时天然承担计时 |

## 3. 还剩的洞（逐项可行性）

### G1 — 自动刷新关闭时，电量数字会挂到过时 · 建议做（P1）

**问题。** `auto_refresh_min` 默认 0。此时仪表盘挂一夜没有任何重绘点，右上角的百分比停在最后一次采样——可能是十几个小时前。这是当前实现里唯一会**显示错误信息**的地方（其它洞只是「没有」）。

**可行方案。** 闲置熄灯到期那一刻本来就要醒（`main.c:787`），顺手采一次 `net_battery()`：百分比或充电态变了，就**只对角标那一小块**发一次 DU。不新增定时器、不新增唤醒、不动整屏。

**成本。** `draw_status_badges()` 现在不返回矩形，需要让它把绘制范围回给调用方（或新增 `ui_redraw_badges()` 返回 `FBInkRect`）。改动集中在 `ui.c` + `ui.h` + `main.c` 那一个分支，约 40 行。

**风险 / 取舍。** 与 `kindle-ui-and-power.md` §5「不引入新的周期重绘」表面冲突。实质不冲突：这里没有新周期，是搭已有的 idle deadline 顺风车；且熄灯后屏幕本来就要保持静止，DU 一个角标不闪页。但若之后把闲置熄灯做成可关（G5），要注意关掉后这条路也没了。

**验收。** 拔掉自动刷新、挂机 30 分钟以上，右上角百分比应跟随实际掉电；期间屏幕不得有整屏闪白。

### G2 — 电量改画五格电池条 · 采纳，建议做（P1）

**决定。** 右上角不再画「87%」，改画一个五格电池：外框 + 芯柱 + 5 个格子，按电量填黑。纯 `ui_fill()` 矩形，**不动字体子集**。

原先「建议不做」的理由（e-ink 上文字更清楚）站不住：五格是墨水屏上最容易一眼读的形态，而且它顺带解决了两个别的问题——见下面「为什么它比数字好」。

**格数映射（含低电量态，G3 并入这里）：**

| 电量 | 格数 | 画法 |
| --- | --- | --- |
| 90–100 | 5 | 常规 |
| 70–89 | 4 | 常规 |
| 50–69 | 3 | 常规 |
| 30–49 | 2 | 常规 |
| 11–29 | 1 | 常规 |
| 0–10 | 0 | **整体反显**（外框与芯柱实心黑、格位留白），即低电量告警态 |
| -1 / 越界 | — | 什么都不画（保持现状语义） |

充电时（`batt_charging == 1`）在电池条左侧保留「充电」二字——两个汉字已在 `glyphs.txt` 里，不必重裁字体，而且比任何用矩形拼出来的闪电符号都不含糊。充电中不进反显告警态。

**几何（全部走 `ui_scale`）：**

- 条高对齐 `px_detail` 的文本高 `th`，条宽约 `ui_scale(30)`，摆在现在百分比文字的位置（`draw_status_badges` 从右往左那一串的最右端）
- 外框 1px（`ui_scale(1)` 且至少 1）：先填黑矩形，再填白内矩形
- 芯柱：外框右侧 `ui_scale(2)` 宽、约半高的黑矩形
- 5 格等分内区，格间留 1px 白缝；填黑即为满格
- **只用 `UI_INK_BLACK` / `UI_INK_WHITE`，不要 `UI_INK_GRAY`**：DU 波形是 1-bit，灰会抖成噪点，而角标刷新（G1）正是走 DU

**为什么它比数字好（这是采纳的实际理由）：**

1. **跳帧判定变干净。** 现在 `frame_batt` 比的是原始百分比，87→86 就算「变了」，会逼出一次视觉上毫无差别的重绘。改比**格数 + 充电态**之后，角标只在跨 20% 边界时才算变——常驻一夜可能一次都不用重绘。
2. **G1 顺带变便宜。** 闲置醒来采样后需要 DU 的次数从「每掉 1%」降到「每掉一格」。
3. **腾出宽度。** 少了 `87%` 这三四个字符，`draw_status_badges` 里给 SSID 的 `cap` 就宽了，长网络名少被截。

**代价，明说：** 分辨率从 1% 降到 20%。1 格覆盖 11%–29%，看不出具体数。这是可接受的——需要精确值的场合是调试，而 `--dump-state` 仍然打印 `battery_level=` 原始百分比；日常挂机只需要知道「还有几格 / 快没电了」。

**成本。** `ui.c` 新增一个 `draw_battery()`（约 40 行 `ui_fill`）+ 一个纯函数 `batt_cells(pct)`；`draw_status_badges` 换掉那段 `snprintf`；`main.c` 的 `frame_batt` 改存格数。字体、配置、`net.c` 都不动。

**验收。** `--demo` 下逐档验证 0/5/10/29/30/89/90/100 的格数与反显；充电中显示「充电」且不反显；读不到电量（-1）时角标位置什么都不画；角标刷新用 DU 且没有灰点抖动。

### G3 — 低电量视觉提示 · 已并入 G2

原方案是「≤10% 时把百分比文字反显」。电池条落地后不需要单独做：0 格 + 整体反显就是告警态，且和 G2 共用同一段几何代码。**不做**弹窗、自动退出、强制唤醒——应用独占屏幕，没有第二块画布，也不该替用户做决定。

### G4 — 非 yoshi 机型读不到电量 · 需真机确认后再做

**问题。** `BATT_SYSFS` 硬编码 `yoshi_battery0`（`net.c:31`），注释说明覆盖 PW2 及之后的 kindlepw2 家族。更新的 MTK 机型（PW5 / Scribe 一类）的电池节点路径不同——**具体路径我无法在这里确认，必须上机 `ls /sys/class/power_supply/` 看**。路径对不上时 `net_battery()` 返回 -1，角标静默消失（不崩，但功能没了）。

**可行方案。** 候选路径表按序尝试，第一个能读出 0–100 的胜出并缓存下标；`sysfs_long()` / `sysfs_charging()` 已经是通用的文件读，改造量很小（约 30 行）。通用回退候选形如 `/sys/class/power_supply/*/capacity` + `status`，但**具体目录名要真机给**。

**前置动作。** 在目标设备 SSH 里跑：

```sh
ls /sys/class/power_supply/
cat /sys/devices/system/yoshi_battery/yoshi_battery0/battery_level 2>&1
/mnt/us/extensions/aiquota/bin/aiquota --dump-state | tail -4
```

第三条能打出 `battery_level=` 非 -1 就说明当前机型没问题，这一项可以直接搁置。

### G5 — 闲置熄灯分钟数可配 · 可做（P2）

现在硬编码 3 分钟（`main.c:157`）。`kindle-ui-and-power.md` §4 已经写了方向：新增 `light_idle_off_min`（0=关此功能，1–60），设置页第五行，复用现成键盘。成本低（`config.c` 一个键 + `settings.c` 一行），但**先在真机上确认 3 分钟是不是真的不合适**再加——加一行设置的代价是设置页从四行变五行，第一版刻意压住了。

### G6 — 电源键短按切前光 · 建议不做（这一批）

`input.c` 只打开触摸设备、只处理 `BTN_TOUCH`（`input.c:201`），电源键事件没人听。要做必须先真机 `evtest`：确认电源键落在哪个 `/dev/input/event*`，以及在包装脚本持有 wake lock 的情况下短按是否还能落到我们打开的 fd（很可能被 powerd 先吃掉）。`kindle-ui-and-power.md` §4 P2 已记录同样的风险。**没有真机实验结论前不要写代码。**

### G7 — 暖光 / `flAuto` · 建议不做

需要 `flWarmth` 一类属性，机型差异大且本机未确认存在。不是需求。

### G8 — 长按 `+` / `−` 连续步进 · 可做可不做

0–24 档从一头调到另一头要点 24 次。`settings.c` 现在只做单击。加按住重复需要在设置页引入一个持续读事件的循环，会把现在「一次 tap 一次处理」的简单形状搞复杂。若真机上觉得点得累再做。

**不建议**把亮度控制搬到仪表盘：底部三个按钮（刷新/设置/关闭）已经排满，加第四个会挤。

## 4. 建议顺序

1. **G4 前置探查**（零代码，SSH 三条命令）—— 先确认电量在目标机上读得到，不然后面全是空转
2. **G2 五格电池条**（P1）—— 排在 G1 前面：G1 的「变了才刷」要建立在格数语义上，反过来做会白写一遍百分比比较
3. **G1 角标不过时**（P1）—— 唯一会显示错误信息的洞；接在 G2 后面改动最小
4. **G5 闲置分钟可配**（P2）—— 真机跑过一周再决定
5. G6 / G7 / G8 —— 不进

G3 已并入 G2，不单独排期。

## 6. 明确不做

- 暖光 / `flAuto`（G7）
- 低电量弹窗 / 自动退出 / 强制唤醒（G2 的反显告警态是全部）
- 为电量新增任何独立定时器或后台轮询
- 把亮度控制放到仪表盘按钮行
- 电源键接管（除非真机实验先给出结论）
