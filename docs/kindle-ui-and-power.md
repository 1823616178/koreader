# Kindle 端：UI 与省电修改规划

对照实现日期：2026-08-30。范围仅 `kindle/` 原生客户端，不改 Usage API、也不改 KOReader 插件。

前光开关和亮度编辑已经进设置页（`light.c` + 设置两行，走 `com.lab126.powerd`，不写配置文件）。本文是那之后还值得做的部分：过夜挂机还能省的电，以及设置/仪表盘上别扭的交互。

**后续文档：** 本文的 P0/P1 项已经落地，核对与后续可行性见 [`kindle-light-and-battery.md`](kindle-light-and-battery.md)（前光/亮度现状、电量改画五格电池条）。另有独立需求 [`kindle-card-popup.md`](kindle-card-popup.md)：点卡片弹出放大框——它引入本文没有的两层东西（卡片命中层、局部模态 + `fbink_rect_dump`/`restore`），所以单独成篇。

## 1. 现状（已经够好的，不要再抠）

常驻仪表盘的功耗形态已经明确，见 [`kindle/README.md`](../kindle/README.md) §5。下列项保持现状，不列入本规划：

| 项 | 现状 |
| --- | --- |
| CPU | 主循环阻塞在 `poll` 等触摸，内核进深 idle |
| WiFi | 谁开谁关；`wifi_auto_off` 默认开；拉完交还射频 |
| e-ink 跳闪 | 自动刷新拉回的数据与屏上签名相同、电量角标也没变，则跳过 GC16 |
| 定时刷新骨架 | `auto_cycle` 不刷「连接中」 |
| 角标 | 只在既有重绘点采样，不轮询、不唤醒 |
| 看门狗心跳 | 30 s 一拍，相对 SoC 底噪是噪声 |

也不要做仪表盘「距下次刷新还有 xx 秒」倒计时：那会逼着周期性闪屏，既费电又伤墨水屏。

---

## 2. 还剩的功耗，按过夜挂机排序

不是按代码量排。墨水屏留住画面不需要 SoC 醒着。

**A. 前光挂着不关（最大、最好做）。**  
常驻时 CPU 和 e-ink 几乎不耗电，前光 LED 却可能是整机第一负载。设置里的开关是手动的：忘了关，灯就亮一夜。现有 `Settings.light_last_on` 已经能记住关掉前的档位。

**B. SoC 被 wake lock 钉死（最大、但伤产品形态）。**  
包装脚本持有 `preventScreenSaver` 和 `/sys/power/wake_lock`，应用每约 4 分钟续期一次。设备不会休眠，待机电流变成常驻底噪。这是「点一下就有反应」换来的。若要过夜很省电，需要可选的「允许休眠」：放开锁，e-ink 继续显示最后一帧，自动刷新用 RTC 叫醒。和当前常驻语义冲突，resume 后锁屏 / framework 冻结要单独验，必须做成默认关的独立功能，不要和关灯绑在一起。

**C. 设置返回的整屏 GC16（小）。**  
设置页 `fbink_cls` 掉了仪表盘，返回必须重画。只开关了灯、没改配置时，这一闪可以比现在的 GC16 轻。

射频唤醒已经是「每周期几秒」，不在本规划里加码。

---

## 3. 原则

1. **闲置关灯不改变常驻语义。** 仪表盘还在，触摸还立刻有反应，只是灯灭了。
2. **亮度调节必须立刻看到灯变**，不要为 0–24 再开一层全屏键盘。
3. **前光状态仍归 powerd。** 闲置关灯、步进、电源键短按都走现有 `light.c`，不写 `extensions/aiquota/config`。若要可调的闲置分钟数，那才是新配置键。
4. **允许休眠是另一次产品决策。** 本文只记方向和风险，不作为第一批实现。
5. **e-ink 上不引入活时钟、不引入新的周期重绘。** 自动刷新是否开启用死文字表示。

## 4. 规划项

### P0 — 闲置关前光，触摸恢复

无触摸 N 分钟后把前光降到 0，记住原亮度；下一次触摸立刻恢复。与设置页「前光关掉记档」共用同一套 last-on。

**默认 N：** 先固定 3 分钟（不必新设置行）。若之后要可调，再加 `light_idle_off_min`（0=关此功能，1–60），不要把第一版做复杂。

**行为：**

- 只在仪表盘 `wait_tap_until` 路径计时。设置页 / 键盘打开期间不算闲置，也不在子页面把灯关掉。
- 计时用 `wait_tap_until` 已有的 deadline 机制，与自动刷新 deadline 取较早者。关灯到期时**不要**走 `ST_LOADING`。
- 关灯：`light_set_intensity(0)`，进程内保存 last-on；不闪屏。
- 恢复：下一次 `input_wait_tap` 返回 tap（`rc == 0`）且灯是被本逻辑关掉的，先恢复再 hit-test。短按电源键若实现了（P2），同样恢复。
- 用户在设置里手动关灯：闲置逻辑不要再把它打开。用一个 `dimmed_by_idle` 标志区分「用户关的」和「闲置关的」。
- 退出应用：若当前是闲置关掉的，退出前恢复 last-on，避免把系统前光留在 0（用户只是离开仪表盘，不是想关灯）。手动关过的保持关。

**主要改动：** `kindle/src/main.c`（deadline 合成、恢复时机）、`kindle/src/light.c`（可选：封装「闲置关 / 触摸开」，避免 main 里散落档位）。设置页不必加行（第一版）。

**验收：** 灯开着，仪表盘挂 3 分钟应变暗；点屏幕灯恢复且按钮仍命中这次触摸（或明确「第一次只唤醒」——第一版选**恢复 + 照常 hit-test**，一次点到按钮）。设置里手动关灯后闲置到期不得把灯打开。点「关闭」退出后，系统前光应回到闲置前的档位。

### P0 — 亮度行内步进，点按立刻变灯

设置页「亮度」不要再 `SET_HIT_EDIT_BRIGHT` 弹数字键盘。0–24 用行内 `−` / `+`，每点一档立刻 `light_set_intensity`。

**布局（同一行，不必把「前光」合并进第一版）：**

- 左：现有「亮度」标签
- 右：`−`  当前档  `+`，两个方块按键，命中区不小于 `ui_scale(48)` 见方
- `−` 到 0 即关灯，「前光」行同步成关（已有 `restore_light_rows`）
- `+` 在关着时从 `light_last_on`（至少 1）打开，与点「前光」开一致
- 按住连加后补，第一版只做单击

键盘继续只服务「接口地址」「自动刷新」。删掉 `SET_HIT_EDIT_BRIGHT` 以及 main.c 里对应的 keypad 分支。

**主要改动：** `kindle/src/settings.c`、`settings.h`、`kindle/src/main.c`。新字形：若只用 ASCII `+` `-` 和已有「亮度」，子集不用扩 CJK；用「减 / 加」则要进 `glyphs.txt` 并重裁字体。

**验收：** 点 `+`/`−` 灯马上变，设置页不整页 GC16（行内 DU，与 WiFi 开关相同）。关到 0 后「前光」显示关；再 `+` 回到上次档位。

### P1 — 设置返回减轻闪屏

设置页已经 `cls`，返回必须重画仪表盘。分支：

- 改了 `api_url`：保持现在的 GC16 + `ST_LOADING` 重拉
- 只改了 WiFi / 自动刷新（配置变了但画面数据没变）或只动了前光：重画后用 GL16（或 DU），不要 GC16
- 什么都没改（看一眼就返回）：同样 GL16/DU

`frame_sig` 在「只动灯」时保持，避免紧接着一次自动刷新又无谓 GC16。

**主要改动：** `kindle/src/main.c` 设置返回那段（约 874–892 行）。

**验收：** 进设置只调亮度再返回，整屏应明显比现在「闪一下变白再回来」轻；改接口地址仍是一次干净 GC16 并重拉。

### P1 — 一眼看出会不会自己更新

自动刷新默认关，标题栏现在只显示 host，常驻时看不出会不会自己拉。不要做倒计时。

在标题栏副标题或「数据接口」卡上加死文字：`自动刷新 5 分钟` / `自动刷新关闭`。优先副标题第二行或现有 subtitle 拼接，避免再加一行卡片高度。

采集时间卡片里已有，标题栏不必再抄 `generatedAt`。

**主要改动：** `kindle/src/ui.c` `draw_title_bar`（或 info card），`ui_draw_dashboard` 增加 `auto_refresh_min` 参数。新 CJK：若用「自动刷新关闭」——「关闭」已有，「自动刷新」设置页已有。

**验收：** 设置为 0 时能看出已关闭；设为 5 能看出 5 分钟。不因此触发额外刷新。

### P2 — 前光与亮度并成一行

P0 步进落地后，设置页仍是「前光」+「亮度」两行，信息重复。合并：左开/关，右 `−` 档位 `+`。五行使设置变长，合并后回到四行（含接口 / WiFi / 自动刷新）。

依赖 P0 步进，不要和步进抢同一轮。

### P2 — 电源键短按切前光

现在 `input_open` 只找多点触摸设备，电源键事件没人听；再叠加 wake lock，按电源往往也睡不着。

更符合 Kindle 习惯：

- 短按：切换前光（关 → last-on，开 → 0）。闲置关掉时，短按视为恢复。
- 长按：现有「关闭」退出（或仍交给系统关机，需在真机确认）。第一版若长按路径说不清，只做短按切灯，长按保持现状。

需要同时打开电源键那个 `/dev/input/event*`（FBInk 的 `INPUT_POWER_BUTTON` 分类可参考）。不要把电源设备误当成触摸板。

**风险：** 与 wake lock 并存时，短按可能仍被 powerd 当成电源事件。真机先 `evtest` 再写死。做之前在设备上确认短按能落到我们打开的 fd。

### 以后单独做 — 允许休眠 / RTC 叫醒

最大的数量级省电，不进入 P0–P2。

方向：可选配置（默认关）放开 `/sys/power/wake_lock`，让 powerd 把机器挂起；e-ink 继续显示最后一帧。自动刷新用 `com.lab126.powerd` 的 `rtcWakeup` 在到期时叫醒 → 拉数 → 画完再睡。

必须单独验证的问题：

- framework 处于 SIGSTOP 时，suspend/resume 会不会画出锁屏
- 部分固件无视 `preventScreenSaver` 仍挂起、醒来即锁屏（这正是现在加 wake lock 的原因，见 `aiquota.sh` 注释）
- RTC 叫醒是否只在 ReadyToSuspend 窗口能设（KOReader `powerd.lua` 的约束）
- 与闲置关灯的次序：先关灯再允许睡

未验证前不要默认开启。

## 5. 明确不做

- 仪表盘活时钟、秒级倒计时、周期性 DU 刷新时间
- 为省电缩短/取消 watchdog 心跳（收益是噪声，检测楔死的窗口会变差）
- 把闲置关灯做成「关灯并且忽略下一次触摸」（除非真机证明恢复+hit-test 会误触）
- 暖光 / `flAuto`（机型差异大，本机未作为需求）
- 改 Usage API、改 KOReader 插件布局

---

## 6. 建议落地顺序

每一项都应能单独合并、单独在设备上验收。

1. **闲置关前光**（P0）— 过夜挂机最明显的功耗，改动面小
2. **亮度行内步进**（P0）— 刚加的亮度用起来最别扭的地方
3. **设置返回减轻闪屏**（P1）
4. **自动刷新死文字**（P1）
5. **两行合并**（P2，依赖 2）
6. **电源键短按**（P2，先真机探事件再写）
7. **允许休眠**（另开文档，先做设备实验）
